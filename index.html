How OTiS works.

OTiS plans a vehicle's whole maneuver in one step. You give it where the vehicle is, how fast it is moving and where it has to be. A neural network answers with a complete plan: 50 thrust commands, one for each moment of the mission.

The network is not trained on examples. It learns by flying practice missions through a physics simulator and measuring, exactly, how every command it chose affected the miss and the fuel. There is no dataset to collect and no trial-and-error reinforcement learning.

The training loop
  1. 1
    Describe the vehicle

    Mass, thrust, drag, gravity, mission time and workspace, or a preset. This defines the physics; it is the only input OTiS needs.

  2. 2
    Invent missions

    Each step draws 1,024 random starts, velocities and goals inside the workspace. The simulator is the data source.

  3. 3
    Plan and fly

    The network outputs a thrust plan for each mission, and the plans are flown through a differentiable exact linear-plant simulator.

  4. 4
    Score

    Every flight gets one number: J = miss² + λ·control effort. Small λ favors accuracy; large λ saves fuel.

  5. 5
    Learn exactly

    Because the simulator is differentiable, the exact gradient of J flows back through every integration step into the network's weights.

After training, a new mission costs a single forward pass: about a millisecond for one plan, and thousands of plans at once on a GPU.

The physics

Thrust-driven vehicles (Rocket, UAV, USV) are a point mass in a plane, state [x, y, vx, vy]:

v̇ = (Fmax/m)·u − (c/m)·v − [0, g]

The throttle u is limited to [−1, 1] on each axis. A mission is 50 commands spread evenly over the mission time, each held for one step and integrated with fourth-order Runge–Kutta. Units are SI.

The network

A residual multilayer perceptron: pre-LayerNorm blocks with GELU and skip connections, from 0.6 M to 51 M parameters.

It is given physics-informed inputs: positions and velocities scaled to the workspace, and the zero-effort miss, which is where the vehicle would end up if it never fired. Its output passes through tanh, so every command stays inside the thrust limit.

What it is compared with

Convex optimization (CVXPY + Clarabel): the way flight systems such as G-FOLD solve this class of problem, re-solved for every mission.

Apollo E-guidance: the classic closed-form steering law. It aims to drive final position error to zero, spending more control effort to do so. Saturation and drag compensation can cause misses even on reachable missions; this bounded law is not a reachability guarantee. It does not try to match a final velocity.

Exact optimum: because this plant is linear, the true best plan can be computed, so the network's distance from optimal is measured, not estimated.

One network per plant

A trained network is valid only for the physics and objective it learned: thrust-to-mass, gravity, drag-to-mass, mission time and λ. OTiS fingerprints each network with those values and shows it only when they match. Change a parameter and the Simulator offers to train a new one.

The stiffness κ in the Simulator predicts how hard that training will be. High thrust-to-weight with a small λ learns slowest.

Honest limits

Training covers linear thrust plants today. The objective scores only the final position and the control effort; the arrival velocity is free, so a mission is an interception (fly-through), not a landing or docking. Missing is penalized rather than forbidden, so the optimizer and the network trade a small miss for less effort; E-guidance aims for zero miss but can miss both unreachable goals and some reachable goals under saturation.

The convex solver returns the provable optimum of this objective. The network returns an approximation without that guarantee, so the Simulator shows how far each network plan is from the optimum, and warns when a network is under-trained. Its case is a fixed, tiny cost per plan that stays fixed as problems grow harder.

Built with

JAX, Flax and Optax for the simulator, network and training (on an RTX 5070 Ti through WSL2); CVXPY with Clarabel and OSQP for the solvers; SciPy for an independent integrator check. The interface is plain HTML, CSS and JavaScript with no build step.
